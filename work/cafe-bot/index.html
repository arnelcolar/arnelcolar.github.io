Case study · Google Apps Script

A café's sales, costs, and stock, logged from Telegram.

Staff type orders into Telegram the way they'd say them out loud, or ask for several in one sentence. The bot prices each item from a menu sheet, logs it to Google Sheets, deducts stock, and replies with a total. Ask for a drink recipe and it reads the recipe sheet. A photo of a supplier receipt becomes an itemized expense.

  • Telegram Bot API
  • Google Sheets
  • OpenRouter vision

How it works

01 / 03

Everything runs in Google Apps Script, so there is no server to host or pay for.

  1. Poll or pushA time trigger polls Telegram for fifty seconds at a time, then hands back to the trigger. The offset is saved in Script Properties so nothing is logged twice. A webhook mode does the same job without the wait.
  2. ParseA typed line splits into quantity, item, and size, then gets priced from the Menu sheet. Sentences that do not fit, like "add kani xl, kani m to my sales", go to the model, which may only answer with items already on the menu.
  3. LogSales, expenses, and inventory live in separate tabs. Each sale deducts ingredients and warns when something drops below its minimum.
  4. Read receiptsPhotos go to a vision model that returns JSON. Personal items are dropped, shop supplies are logged and restocked, and one follow-up sentence corrects a wrong call.

Keys stay out of the code

The bot token, API key, and sheet ID live in Script Properties. The code can be shared or pasted into a chat without handing over access.

var TOKEN = PROPS.getProperty("TELEGRAM_TOKEN");

Reading an order

One regular expression turns "2 kani-mango s" into a quantity, an item, and a size. When the size is left off, it defaults to 16.

function parseOrder(text) {
  var lower = text.toLowerCase().trim();
  var match = lower.match(/^(\d+)\s+(.+?)(?:\s+(\S+))?$/);
  if (!match) {
    return { error: 'Format: "1 latte 16" or "2 kani-mango s"' };
  }
  return {
    qty: parseInt(match[1], 10),
    item: match[2].trim(),
    size: match[3] || "16",
    error: null
  };
}

Only menu items count

A sentence with several drinks has no fixed shape, so the menu is handed to the model with the message and the model may only answer with names and sizes that already exist. Anything missing from the reply is dropped rather than guessed.

var prompt = "Parse the user's message into a JSON list of orders.\n" +

  "Return ONLY valid JSON: " +
  "{\"orders\":[{\"qty\":number,\"item\":\"menu item\",\"size\":\"size\"}]}\n" +
  "Only include items that exist in the available menu list.";

var payload = {

Parsing the model's reply

Models sometimes wrap JSON in prose or code fences. The bot cuts out the first object it finds before parsing, and retries up to three times when the API errors.

var start = textResponse.indexOf('{');
var end = textResponse.lastIndexOf('}');

if (start !== -1 && end > start) {
  textResponse = textResponse.substring(start, end + 1);
} else {
  textResponse = textResponse
    .replace(/```json/g, "").replace(/```/g, "").trim();
}
